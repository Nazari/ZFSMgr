## ZFSMgr 1.1.0 — command line

Still the command line client (`zfsmgr-cli`) and its daemon (`zfsmgr-agent`) only; the
graphical interface is planned for **2.0.0**.

Asset: `zfsmgr-cli-1.1.0.zip` (+ `.sha256`), one installer per system inside. Once one
machine has it, `install-daemon -a` brings the daemon and the CLI up to date on every
connection.

### New

- **Compressed stream files in `send`**: `send <file> --comp gzip|lz4|zstd[:level]` stores
  the stream compressed, and `send --from <file>` reads it back with no option: the format is
  recognised by its first bytes, not by the extension. The machine that holds the file
  compresses or decompresses it; the ZFS end sends or receives the raw stream. A compressed
  file that is cut short or damaged fails with its reason before `zfs recv` takes it.
- **Looking inside an unmounted dataset**: `ls`, `cd`, `info` and `cp` from `#content` mount
  it read-only in a temporary directory, without touching its properties, and release it
  afterwards (Linux and FreeBSD; not on macOS, whose `mount_zfs` ignores read-only, nor on
  Windows).
- **`breakdown` and `assemble` of an unmounted dataset**, such as a boot environment with
  `mountpoint=/`: it is mounted on a temporary place while the operation lasts and gets its
  mountpoint back, with its origin, without mounting anything over the running system. The
  confirmation warns when the pool is imported at boot and the new children would cover the
  machine's own `/usr`, `/var`…

### Changed

- **`cp` treats the target like the usual `cp`**: into an existing directory with its own
  name; a target that does not exist IS the copy (a file under that name, a directory created
  with its contents); a file overwrites another file. A missing source is reported before
  anything starts. The landing directory keeps the original's owner, mode and date.
- **`load-key`** looks at the dataset before asking: nothing is asked for a dataset that is
  not encrypted or whose key is already loaded; on a child that inherits encryption it loads
  its encryption root's key and says so; a key in a file (`keylocation=file://`) is read from
  there. `--password-fd` for scripts.
- TAB completes `..` and `.` with their slash.
- When the first connection with a password is created, the new master password is asked
  for twice.
- `help <command>` with options warns that it runs nothing.

### Fixed

- `breakdown`/`assemble` on a dataset with `canmount=off` refuse before the confirmation,
  instead of failing after it.
- `assemble` and `todir` on macOS failed on any dataset indexed by Spotlight
  (`.Spotlight-V100` cannot be read, even by root); the system's per-volume folders are now
  left out.
- Untranslated texts: the passphrase prompt, syntax errors, configuration warnings and the
  end of a job.
- The README explains how to start: connections have to be created before
  `install-daemon -a` can reach them, and scripts feed the shell through standard input.

## ZFSMgr 1.1.0 — línea de órdenes

Sigue siendo solo el cliente de línea de órdenes y su daemon; la interfaz gráfica, en la
2.0.0. Lo nuevo: **ficheros de flujo comprimidos en `send`** (`--comp gzip|lz4|zstd[:nivel]`
al escribir; al leer se reconoce el formato por los primeros bytes), **mirar dentro de un
dataset sin montar** (montaje temporal de solo lectura, en Linux y FreeBSD) y
**`breakdown`/`assemble` de un dataset sin montar**, como un entorno de arranque con
`mountpoint=/`. Cambia: `cp` interpreta el destino como el `cp` de siempre y conserva el dueño
del directorio de llegada; `load-key` mira el dataset antes de pedir la frase, carga la de su
raíz de cifrado y admite `--password-fd`; el tabulador completa `..`; la maestra nueva se pide
dos veces. Arreglado: `canmount=off` se avisa antes de confirmar, Ensamblar en macOS con
Spotlight, varios textos sin traducir y el README.
