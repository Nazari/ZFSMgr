## ZFSMgr 2.0.0rc4 (release candidate)

The fourth candidate of 2.0: [2.0.0rc3](https://github.com/Nazari/ZFSMgr/releases/tag/v2.0.0rc3)
with an interface that shows what it is waiting for.

Asset: **`zfsmgr-2.0.0rc4.jar`** (+ `.sha256`), the installer. With Java 21 or later, open it
(`java -jar zfsmgr-2.0.0rc4.jar`, or a double-click): it installs on this computer, then shows
your network and installs or updates ZFSMgr on the machines you mark. Without Java the .jar is
also a zip: unzip it and run the installer of your system in `zfsmgr-2.0.0rc4/`.

### Interface

- **What may be about to change is greyed**, with the wait cursor over it, from the moment it
  is asked until its answer is painted. A refresh no longer shows nothing and then repaints by
  surprise. What only the interface changes, and has not, stays as it is:
  - Status: each machine's card until that machine answers, and the Pools and Jobs tiles; not
    the number of machines nor the scheduled copies. «Refresh» waits for the reading it started.
  - Copies: the copy you pause, change, run or stop, until its machine answers again.
  - Machines: the detail while a command runs, and the pools it reloads, also in the tree.
  - Jobs: what is running while the machines are read, and what finished while their histories
    are.
  - Administration: the programs and «Between machines» whenever the page reads again; the
    connections and the keys after you change them.
- **A copy shows what it brought when it ends.** A copy runs as a job: the interface now follows
  it, reads the open pools again when it finishes and says in the status line how it ended
  —done, failed with the reason, or stopped—. Before, the new dataset only appeared after opening
  the interface again, and a failed copy said nothing.

### Known limitations

- Copying or levelling with a Windows machine as the ZFS end is still refused; use «todir» and
  «fromdir». Allowing it was tried: OpenZFS on Windows (zfswin-2.4.1rc17) fails every
  incremental and replication stream read from a pipe, and receiving a real dataset brought the
  machine down (`VERIFY3U(drrw->drr_logical_size > dn->dn_datablksz)` in `dmu_recv.c`).
