## ZFSMgr 1.4.2 — command line

Still the command line client (`zfsmgr-cli`) and its daemon (`zfsmgr-agent`) only.

Asset: `zfsmgr-cli-1.4.2.zip` (+ `.sha256`), one installer per system inside.

**Update every machine**: after installing the new client, run `install-daemon -a`.

### Changed: the installers

- **New names**: `install-linux.sh`, `install-macos.sh`, `install-freebsd.sh` and
  `install-windows.cmd` (they were `instalar-*`).
- **Options in English**, and the Spanish ones are gone:

  | Unix | Windows |
  |---|---|
  | `--prefix <path>` | — |
  | `--cli-only` | `-CliOnly` |
  | `--with-daemon` / `--no-daemon` | `-WithDaemon` / `-NoDaemon` |
  | `--force` | `-Force` |
  | `--dry-run` | `-DryRun` |
  | `--uninstall` | `-Uninstall` |
  | `--accept-experimental` (FreeBSD) | — |
  | — | `-Quiet` |
  | `-h`, `--help` | `-Help` |

- **Messages in the system's language**: Spanish when the locale is Spanish (on Windows, the
  language of the interface), English otherwise. What the CLI prints while installing follows
  the same language.

### New: the Windows installer installs the local daemon

On a Windows machine with OpenZFS, `install-windows.cmd` now offers to install or update the
daemon of that machine, as the Unix installers do (`-WithDaemon` installs it without asking).
It is the same scheduled task, firewall rule and certificates that `install-daemon` sets up
over SSH. Before reinstalling it asks the running daemon for jobs in progress, so a copy is
not cut halfway, and `-Uninstall` removes the daemon too.

`zfsmgr-cli install-daemon-local` works on Windows now, and its options are `--check` (says
what it would do), `--check-jobs` and `--force`.
