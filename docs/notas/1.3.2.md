## ZFSMgr 1.3.2 — command line

Still the command line client (`zfsmgr-cli`) and its daemon (`zfsmgr-agent`) only.

Asset: `zfsmgr-cli-1.3.2.zip` (+ `.sha256`), one installer per system inside.

**Update every machine**: after installing the new client, run `install-daemon -a`. The fix
is in the daemon that receives a levelling, so the target machines need it too.

### Fixed

- **A recursive schedule copied itself to the target.** A recursive levelling sends with
  `zfs send -R`, which carries the dataset's properties, and the schedule is stored in them
  (`org.zfsmgr:schedule-*`). The target ended up with a copy of the source's schedule. It
  never ran —the daemon only runs schedules set on that machine— but it was listed as one of
  the target's schedules. A levelling now receives without those properties.
- **The list of schedules showed received ones.** It now shows only those set on each
  dataset, the same ones the scheduler runs.
