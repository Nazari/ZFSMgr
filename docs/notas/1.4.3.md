## ZFSMgr 1.4.3 — command line

Still the command line client (`zfsmgr-cli`) and its daemon (`zfsmgr-agent`) only.

Asset: `zfsmgr-cli-1.4.3.zip` (+ `.sha256`), one installer per system inside.

**Update every machine**: after installing the new client, run `install-daemon -a`.

### Security: the sudo password no longer appears in a command line

Up to 1.4.2, when a connection used sudo with a password, the CLI put that password
(octal-escaped, which hides nothing) inside the command it ran over SSH. While that command
ran, any user of the local machine could read it with `ps` in the arguments of `ssh`, and any
user of the remote machine in the arguments of `sh -c`. It happened when reading the daemon's
certificates, in `install-daemon`, `holds`, and the `fromdir` pipeline between machines.

Now the password goes to `sudo -S` as the first line of the command's standard input, and
never in an argument or in the environment.

If you used 1.4.2 or earlier on a machine shared with other users, consider changing the sudo
passwords of the connections that had one.

### New

- `overview [<connection>] [-a]`: the state of a machine in one answer — reachable, daemon
  version, pools with their health, schedules and their last copy, running jobs — and the
  warnings, already written, errors first. `--format json` gives fixed codes for a program to
  read.
- `zfsmgr-cli --serve` reads `config.json` again when another process changes it, and its
  protocol is written down in `docs/protocolo_serve.md`.
