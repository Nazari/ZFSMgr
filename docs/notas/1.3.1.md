## ZFSMgr 1.3.1 — command line

Still the command line client (`zfsmgr-cli`) and its daemon (`zfsmgr-agent`) only.

Asset: `zfsmgr-cli-1.3.1.zip` (+ `.sha256`), one installer per system inside.

**Update every machine**: after installing the new client, run `install-daemon -a`. Several of
the fixes below are in the daemon (the scheduler, the Windows service, SSH), and on Windows the
reinstall is what applies the new settings of the daemon's task.

### New

- **`create <pool> … --opts-as zfsm://connection/pool`** creates a pool with the options of
  another one: the properties chosen for that pool (`ashift`, `autotrim`, `compatibility`…)
  as `-o`, and those of its root dataset (`compression`, `atime`…) as `-O`. It leaves out
  what makes no sense on a new pool —features, import-time properties, the mount point, the
  encryption, user properties such as the snapshot schedule— and those set to their default
  value. In the shell it creates nothing yet: the command comes back at the prompt with the
  options written out, to review and press Enter.
- **Absolute names in `create`**: `/connection/pool` and `zfsm://connection/pool` work from
  anywhere, also for datasets.
- **`<command> --help`** shows the command's help.
- **The help** says in every command that names are written relative, absolute or as a full
  URL, and its examples use generic machine names.
- **`devices`**: one row per device and an ID column with its stable
  `/dev/disk/by-id/…` path, the one to use when creating a pool. Every alias is still in
  `--format json`/`tsv`.

### Fixed

- **Recursive schedules went red when pruning the target** («could not find any snapshots
  to destroy») the first time a snapshot fell out of the retention: the receive had already
  removed it. The target was fine; now the prune only touches what is still there.
- **`install-daemon --on <machine> --check` installed.** It now shows what it would do and
  touches nothing, as with `-a`.
- **On Windows, `install-daemon` did not check that OpenZFS was there** and installed a
  daemon with no pool to see. It now asks `zfs version`.
- **A machine that could not be reached was reported as «has no OpenZFS».** Now it says it
  could not be asked, with the reason.
- **The Windows daemon stopped when a laptop went on battery** —and did not start on
  battery, stopped after 72 hours and never restarted—. Its task now keeps running, has no
  time limit and restarts itself.
- **Commands to a machine whose network had dropped waited out their whole timeout**
  through a dead shared SSH connection. Those connections now notice it in under a minute.
- **SSH commands to Windows waited for their timeout** even after answering. They now end
  when the command does.
- **`edit` of a Windows connection always warned that the credentials do not elevate.** It
  now checks whether the user is an administrator.
- **`create -n` of a dataset said «created»** and the output of `zfs -v`/`-n` was lost.
- **The help of `schedule`** named properties and an agent that no longer exist.
