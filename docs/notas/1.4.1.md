## ZFSMgr 1.4.1 — command line

Still the command line client (`zfsmgr-cli`) and its daemon (`zfsmgr-agent`) only.

Asset: `zfsmgr-cli-1.4.1.zip` (+ `.sha256`), one installer per system inside.

**Update every machine**: after installing the new client, run `install-daemon -a`. The fixes
are in the daemon, on both ends of a pull.

### New

- **`zfsmgr-cli --version`** (also `-V`) prints the version, like `zfsmgr-cli version`.

### Fixed

- **The first pull of an ENCRYPTED origin always failed.** It was received over the empty
  dataset that holds the schedule, and ZFS refuses to overwrite an unencrypted dataset with an
  encrypted stream. The empty dataset is now moved aside and destroyed once the copy is in, or
  put back if the receive fails. The copy stays encrypted on the backup, without the key.
- **A copy that was already up to date did not hold its base on the origin** until its next
  send, so the origin's prune could take it. It is held on every pass now.
- **Writing a pull schedule said the origin's daemon was out of date** unless both were the
  very same build. Any 1.4 or later is accepted.
- **A push to a machine that only has a pull credential** now says so («needs the full
  credentials: `peers --push`») instead of a generic refusal.
- **`ls` of a machine with a disk that does not answer** (a stuck USB drive) hung and ended in
  a TLS error, because looking for importable pools scans every disk. That search now runs in
  the background with a time limit: the listing comes back within 15 s with a warning, and
  the importable pools appear once the search ends.
