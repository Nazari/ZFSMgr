## ZFSMgr 1.2.0 — command line

Still the command line client (`zfsmgr-cli`) and its daemon (`zfsmgr-agent`) only; the
graphical interface is planned for **2.0.0**.

Asset: `zfsmgr-cli-1.2.0.zip` (+ `.sha256`), one installer per system inside.

**Update every machine.** The client and the daemons of 1.2.0 do not talk to those of 1.1.0
(error codes, the scheduler's properties, the tree transfer). After installing the new
client, run `install-daemon -a`. Schedules created with 1.1.0 have to be set again with
`schedule` (the properties are now `org.zfsmgr:schedule-*` and the target a `zfsm://` URL).

### New

- **Scheduled snapshots you can watch**: `schedule status [-a|<connection>]` shows the last
  snapshot, pruning and levelling of each schedule, in green or red with the reason;
  `schedule run [--wait]` runs one now; on start-up the shell says whether all schedules are
  green or which failed and why.
- **Levelling a schedule** finds the common base by GUID and sends with `-I`, prunes the
  target together with the source (never the base), runs as a daemon job that can be seen,
  resumed and cancelled, and a period with no changes renames the last snapshot instead of
  spending retention on an identical one.
- **The shell screen**: the command line wraps over several rows, tables are redrawn when the
  window is resized, and a status area at the bottom shows the position, schedules, the last
  error and running jobs. `--no-tui` turns it off.
- **Agent errors in your language**: the daemon answers with codes and the client words them.

### Changed

- **No more `rsync`.** `rsync` (the command) and every copy use the agent's own engine,
  within one machine and between machines. Measured attribute by attribute against
  `rsync -aHWS -A -X`: owner (by name), mode, nanosecond timestamps, symbolic and hard links,
  special files, holes, ACLs and extended attributes are kept. Between different systems,
  what the target cannot hold (a Linux ACL on FreeBSD, any ACL on Windows) is reported.
  Timestamps are compared to the nanosecond, so a change within the same second is seen.
- `rsync --check` / `cp --check` list one change per line: `+` new, `!` changes type,
  `>` contents, `.` metadata only, `-` deleted.
- `schedule --to` takes only a `zfsm://` URL.

### Fixed

- A file name Windows cannot represent, arriving in a tree copy, brought the whole daemon
  down.
- A directory that could not be read at the source looked empty, and with `--delete` its copy
  was emptied.
- A copy stopped at the first entry that changed type (a directory that became a file).
- `install-daemon` reset the daemon's listening address to 127.0.0.1, undoing
  `peers --listen`.

## ZFSMgr 1.2.0 — línea de órdenes

Sigue siendo solo el cliente de línea de órdenes y su daemon; la interfaz gráfica, en la
2.0.0. **Hay que actualizar todas las máquinas** (`install-daemon -a`): la 1.2.0 no habla con
la 1.1.0, y las programaciones se vuelven a poner con `schedule`. Lo nuevo: `schedule status`
y `schedule run`, aviso al arrancar del estado de las programaciones, nivelación por GUID con
`-I` como trabajo del daemon y poda del destino; la pantalla del intérprete (línea
multilínea, tablas que se recomponen, zona de estado); los fallos del agente en el idioma de
quien lo lee. Cambia: **ya no se usa `rsync`**, toda copia va con el motor propio, dentro y
entre máquinas, con la paridad medida (dueños, fechas al nanosegundo, enlaces, especiales,
huecos, ACL y xattr), y `--check` lista los cambios. Arreglado: un nombre no representable en
Windows tiraba el daemon; un directorio ilegible ya no vacía su copia; un cambio de tipo ya no
corta la copia; `install-daemon` ya no deshace `peers --listen`.
