## ZFSMgr 1.3.0 — command line

Still the command line client (`zfsmgr-cli`) and its daemon (`zfsmgr-agent`) only; the
graphical interface is planned for **2.0.0** (see below: its review has started).

Asset: `zfsmgr-cli-1.3.0.zip` (+ `.sha256`), one installer per system inside.

**Update every machine**: after installing the new client, run `install-daemon -a`. The
daemon has new verbs that the new commands need; the status area tells you which daemons are
older than the client.

### New

- **Faster start-up.** The shell opens the stored secrets once and in parallel: from about
  1.8 s to about 0.1 s before the prompt.
- **`zfsmgr-cli --serve`: the shell as a service for another program.** One JSON command per
  line in, JSON events out (confirmations, secrets, the result with its tables). The master
  password comes through the pipe, never in the arguments or the environment. A command that
  fails does not end the service. It is what the graphical interface is being rebuilt on.
- **`fromdir --delete-source`** deletes the source directory, but only after copying it and
  checking with a dry run of the tree that nothing differs; it asks first. It refuses a source
  inside a ZFS dataset, `/` or a first-level directory, and on Windows.
- **`send --level`** finds the newest snapshot both sides share by GUID and sends from it.
- **`create` of an encrypted dataset with a passphrase**: the passphrase goes to the daemon
  through a pipe.
- **Connections**: `create`/`edit --family auto|ipv4|ipv6` (which addresses ssh tries) and
  `edit --no-key` (log in with the password again).
- **`schedule --no-to`** removes a schedule's target.
- **`clone -p -u prop=value`**: create missing parents, do not mount, set properties.
- **`unallow`** with scopes (local, descendants) and `--create` without a recipient.
- **`breakdown --list` helps you choose**: it shows the first level of directories with the
  size and number of files under each one, instead of every directory down to the last
  (10,790 lines for a Calibre library with two folders at the top). `--depth <n>` goes
  further down, `-r` lists every level. A child dataset mounted inside is neither listed nor
  added to the sizes.
- **New listings**: `ls -r` (the whole tree), `ls #properties --pool`, `accounts [--groups]`
  (the machine's users and groups); `devices` tells which pool each disk belongs to and whether it is imported; pools
  show their GUID and why they are in their state.

### Fixed

- **The status area** now follows the connections: adding or reconnecting one with schedules
  shows them at once, instead of «no schedules» until the shell was restarted.
- **`schedule` and `schedule status` with no schedules** printed nothing in `--format json`
  or `tsv`; now they print an empty table.
- **`create`/`edit` of a connection without a terminal** created it without the password.
- **An English message** read arguments that were not there (a stale printf format).

### The graphical interface: review started

The review of the graphical interface (`src/native`) has started, aiming at its **first
release in 2.0.0**. It is still not published with 1.x. The approach:

- **The window has no business logic of its own.** It starts a `zfsmgr-cli --serve` and every
  action of its menus is the same command line you would type in the shell: same checks,
  same messages, same result. What the shell could not do yet was added to the shell (most of
  the «New» list above), with its test, not to the window.
- **Reads go through the shell too**: the dataset tree, properties, permissions, schedules,
  jobs, files and devices come from `ls`, `schedule status`, `jobs`, `devices`… in JSON. The
  window no longer has its own SSH, tunnels or TLS to the machines.
- **A simpler window, closer to the shell**: a status bar like the shell's status area, a
  Jobs box with every daemon job, a Schedules tab, and the logs in their own windows.
- About 16,000 lines of the window's code are gone so far.

What is left before 2.0.0 is testing it by hand on every system and closing what that finds.
