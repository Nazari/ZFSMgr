# 操作：同步快照

> **如何发起。** 用右键把源标记出来（`标记为源`），然后**在目标节点上**打开右键菜单：
> `与源 …` 子菜单中提供该操作。按钮已经取消。若显示为灰色，原因见其工具提示。
> 参见 `右键菜单`。

目标：借助快照/数据集，让源与目标的状态对齐。

条件：

- 源：数据集或快照。
- 目标：数据集。
- 源与目标都必须使用 `2.3.3` 或更高版本的 OpenZFS。

对齐要求（不满足时操作会带提示取消）：

- 该操作**始终是增量的**（`zfs send -I`），从目标最新的快照推进到源的目标快照。
- 目标必须**至少有一个快照**。
- 目标最新的快照也必须存在于源中。对应关系**按 GUID 判定，而不是按名称**：同名但 GUID
  不同的两个快照不算数。
- 目标的那个快照不能比源的目标快照更新。
- 若源与目标已经一致，会告知已对齐并且不做任何事。

行为：

- 加入队列前会弹出 `zfs send` 选项对话框。
- 若目标的守护进程处于活动状态并支持后台任务（`JOBS_SUPPORT=1`）——当两端是不同连接时，
  源也需要如此——且两端都不是 Windows，则传输会作为**后台任务**启动：
  - 数据在两个守护进程之间直接流动，不经过运行 ZFSMgr 的这台机器。
  - 界面不会被阻塞；进度显示在 **传输** 分页中。
  - 可以关闭界面，传输仍会在守护进程中继续。
  - 任务可以从传输分页取消。
- **若任一端是 Windows，该操作不可用**：Windows 代理尚未实现跨机器的数据流传输。
- 若不支持后台任务，操作会退回同步模式：加入 `待应用更改`，在应用更改时执行。
- 当源与目标位于**同一连接**时，`zfs send | zfs recv` 管道由守护进程自己搭建
  （`--zfs-pipe-local`），不经过远程 shell。该路径下**不显示进度行**；只有后台任务路径
  才能看到进度。
- 所选择的传输方式记录在 INFO 级别，待应用更改记录在 NORMAL 级别。
- 若任一连接低于 `2.3.3`，该操作会被阻止。
