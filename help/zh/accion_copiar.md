# 操作：复制

> **如何发起。** 用右键把源标记出来（`标记为源`），然后**在目标节点上**打开右键菜单：
> `与源 …` 子菜单中提供该操作。按钮已经取消。若显示为灰色，原因见其工具提示。
> 参见 `右键菜单`。

目标：从源发送一个快照，并在目标接收。

条件：

- 源：已选中的快照。
- 目标：已选中的数据集。
- 源与目标都必须使用 `2.3.3` 或更高版本的 OpenZFS。

行为：

- 使用 `zfs send` 与 `zfs recv`。加入队列前会弹出 `zfs send` 选项对话框。
- `zfs recv` 的真实目标是 `<目标数据集>/<源的叶名称>`，除非目标已经以该名称结尾。
- 若目标的守护进程处于活动状态并支持后台任务（`JOBS_SUPPORT=1`）——当两端是不同连接时，
  源也需要如此——且两端都不是 Windows，则传输会作为**后台任务**启动：
  - 数据在两个守护进程之间直接流动，不经过运行 ZFSMgr 的这台机器。
  - 界面不会被阻塞；任务立即开始，应用程序仍可继续使用。
  - 进度显示在 **传输** 分页中（已传输量、速度与耗时）。
  - 可以关闭界面，传输仍会在远端守护进程中继续。
  - 当一个带守护进程的连接重新可用时，其进行中的任务会自动恢复，并重新出现在传输分页里。
  - 每个任务都可以从传输分页取消（向 `zfs send` 进程发送 `SIGTERM`）。只能取消正在运行的任务。
- 若不支持后台任务，操作会退回同步模式：加入 `待应用更改`，在应用更改时执行。
- 当源与目标位于**同一连接**时，`zfs send | zfs recv` 管道由守护进程自己搭建
  （`--zfs-pipe-local`），不经过远程 shell。该路径下**不显示进度行**；只有后台任务路径
  才能看到进度。
- **若任一端是 Windows，该操作不可用**，尝试时会说明原因。跨机器传输数据流需要 Windows
  代理尚未实现的管道；早先使用的 `tar` 退路依赖远端机器上的 Unix shell，现已不再使用。
- 结束时会刷新**目标**连接及其内容。
- 若任一连接低于 `2.3.3`，该操作会被阻止。
