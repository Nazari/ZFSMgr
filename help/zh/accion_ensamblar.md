# 操作：组装

目标：把子数据集并入父数据集，其内容保留为目录。

条件：

- **在 Windows 连接中可用**，与 `拆分` 不同。已在真实机器上验证：数据集会原地变回目录。
- 在池树中选择数据集。
- 父数据集必须处于**已挂载**状态；否则操作会以 `mountpoint=none` 失败。所选的各个子数据集由代理自行挂载。
- 在 Unix 连接上需要安装 `zfsmgr-agent` 代理：没有 shell 备用方案。

## 选择要并入的数据集

选择窗口有两列：目录，以及**它当前所属的数据集**。这里的名称是事实而非建议，因此不可编辑。

子数据集**各自独立选择**：并入某一个并不强制并入其下的其他数据集。

## 执行内容

- 显示命令并请求确认，随即执行，期间界面会被阻塞。
- 内容会复制到**池内部**的暂存区，最后一步是重命名而非第二次复制：数据不会传输两遍。
- **被并入数据集之下的子数据集会被保留。** 它们不会被销毁：而是改挂到父数据集之下，并保持原有挂载位置，因此内容不受影响。
- 改挂时，名称会编码**它们所挂载的位置**：即父数据集下的路径，用 `:` 代替 `/`。

```
testpool/user/bin/Squirrel.app/Contents   （之前）
testpool/user/bin/Squirrel.app:Contents   （之后，挂载位置不变）
```

这样名称保留了路径信息，之后的「拆分」操作可以据此还原。数据集名称不再与目录结构一致，这是预期行为：ZFS 并不要求两者相同。

- *进度*框每两秒输出一行，包含当前项目、已复制的大小和速度。

## 重要提示

- 中间空间取自**池本身**，而非系统 `/tmp`。在多数 Linux 发行版中 `/tmp` 位于内存中，使用它会导致无法组装较大的数据集。
- 销毁源数据集之前会**校验复制是否完整**；若有缺失，操作会中止且数据集**不会被销毁**。
- **仅**销毁所选的数据集，不使用 `-r`：其后代此前已完成改挂。
- 当系统的 `rsync` 支持时，复制会保留 **ACL 和扩展属性**（自动检测）。
