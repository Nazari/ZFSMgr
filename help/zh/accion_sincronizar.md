# 操作：同步文件

> **如何发起。** 用右键把源标记出来（`标记为源`），然后**在目标节点上**打开右键菜单：
> `与源 …` 子菜单中提供该操作。按钮已经取消。若显示为灰色，原因见其工具提示。
> 参见 `右键菜单`。

目标：把源数据集的内容同步到目标数据集。

条件：

- 源：已选中的数据集。
- 目标：已选中的数据集。
- 源与目标必须不同，且两者都已挂载。若两端对应的子数据集都已挂载，也接受 `canmount=off`。
- 源与目标都必须使用 `2.3.3` 或更高版本的 OpenZFS。

行为：

- 在 Unix 连接上，通过守护进程使用 `rsync`（`--mutate-rsync-local`）：由守护进程自己探测
  rsync 的能力（`-A` 用于 ACL，`-X` 用于扩展属性，`--info=progress2`）并执行命令，不构造
  任何 shell 命令。两端都必须有代理，否则**不进行同步**：在打开选项对话框之前就会给出原因，而不是先问您要
什么、然后又做不到。
- 在 Windows 上，**同一台机器的两个数据集之间**使用代理自带的复制功能
  （`--mutate-copy-tree`），无需 `rsync`。它是真正的同步：跳过已相同的内容，支持
  `--delete`，也能模拟运行，因此 `Check` 与 Unix 上表现一致。
- 在 Windows 上**跨机器**时，仍然使用基于 SSH 的 `tar`（若两端都有则用 `zstd` 或 `gzip`），
- **在 Windows 上，同步不会删除目标端的内容。** 那条 `tar` 管道只做添加和覆盖，不会清除多余
  的文件：删除选项在那里不生效。已从一台 Unix 机器到一台 Windows 机器验证。在 Unix 上会删除，
  因为走的是通过代理的 `rsync`。
  且**不带 `--delete`**：这种情况下它不是同步，而是复制。
- 在 Linux、macOS 与 FreeBSD 上，未挂载的数据集可以通过临时的替代挂载来同步：代理会移动
  它的挂载点，传输完成后再恢复。
- 按下后会弹出 *同步选项* 对话框，可在其中启用或禁用 `--delete`（跨机器的 tar 模式
  下不可用），并发起 `Check`（预演），其输出直接显示在该对话框中。
- **按下即执行。** 以前会加入待应用更改列表，等您统一应用；该列表已经取消。
- rsync 的输出在操作结束时写入日志。经由守护进程的路径**没有实时进度行**。
- `Check`（预演）可以从对话框取消。真正执行一旦开始就无法取消。
- 若任一连接低于 `2.3.3`，该操作会被阻止。

关于中断：

- 如果使用临时挂载的同步被强行中断，数据集可能停留在某个临时目录上。请在连接的右键菜单中
  使用 `修复临时挂载点` 予以恢复。
